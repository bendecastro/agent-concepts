## Harness portability bug — found and fixed

`run-pressure.py` resolved `CANDIDATE` as `parents[4]` of the script and expected
`<candidate>/agents/concepts/bc-drain-issues` alongside `<candidate>/.pi/agent/agents/`.
Those were siblings when this workspace lived in CONFIG. The workspace now sits at
`Work/PUBLIC/Agents` while the Pi roles remain in CONFIG, so the default invocation
aborted with `missing Pi role bc-drain-auditor` at HEAD, before any edit. The 23/23 run
above used a two-symlink shim passed as `argv[1]`.

Fixed the same day by separating the two roots, which were never one root:

- `WORKSPACE` — derived from the script's own location (`parents[3]`), overridable with
  `BC_DRAIN_WORKSPACE`. Supplies the concept body and the policy path.
- `PI_DIR` — defaults to `~/.pi/agent`, the live directory Pi actually reads, overridable
  with `BC_DRAIN_PI_DIR`. Supplies the role files and the subagent extension config.

Both are preflighted with an actionable error naming the override. The positional
argument was dropped; no documented invocation used one.

Verified: default invocation with no arguments and no shim passes **23/23**; the runner
works from an unrelated cwd; `BC_DRAIN_WORKSPACE=/tmp` and `BC_DRAIN_PI_DIR=/tmp/nope`
each produce the intended error rather than a confusing assertion.

## Finding: check 1's policy-mutation evidence is inert (not fixed)

Noticed while translating the paths. Check 1 claims the harness "never edits policy". Its
evidence cannot support that claim, for three independent reasons:

1. `policy_path` pointed at `agents/policies/publish.yaml`, which does not exist — the
   repository holds `publish.example.yaml`, and the real user-owned policy lives outside
   this workspace at `~/.config/agent-concepts/publish.yaml`. So the hash is `'absent'`.
2. `policy_hash_after` is assigned the *same Python variable* as `policy_hash_before`. It
   is not a second measurement; the two fields are equal by construction.
3. Nothing asserts the two are equal. The pair is recorded as evidence, never compared.

The evidence would read identically whether or not the policy had been rewritten — the
exact class the discriminating-evidence rule added in this same change forbids, sitting in
the harness that verifies that rule. Left unfixed because the correct subject is the real
user-owned policy outside this repository, and pointing a test at it is a decision for the
user. The path translation preserved existing semantics rather than silently changing what
check 1 asserts.
