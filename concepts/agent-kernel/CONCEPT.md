# Concept: agent-kernel

A tiny always-injected base instruction file for coding-agent harnesses. It defines the user's default agent posture — act on mechanical work but consult on judgment calls, preserve context economy, use tools, verify, respect dirty worktrees, and load deeper concepts only when relevant.

The deliverable is `body/AGENT-KERNEL.md`, intended to be pasted, included, or referenced from a harness's main agent file. It is deliberately not an Agent Skill: skills are on-demand; this is bootloader context.

## Design decisions

- **Kernel, not constitution** — always-on instructions must be small enough to avoid context rot. This file names durable defaults and delegates specialized behavior to skills/concepts.
- **General before prescriptive** — it states posture and failure modes rather than long procedures, following the right-altitude guidance in `prompting-agents`.
- **Skill-loading policy is load-bearing, implemented as an index pointer** — the kernel points at `index.md` instead of hardcoding concept names, so the catalog can evolve without editing always-on text in N harnesses. To avoid over-eager reads, it consults the catalog only when specialized handling would materially affect the outcome.
- **No harness syntax** — the body avoids tool names, slash commands, and frontmatter so it can be absorbed into Claude, Pi, Codex, OpenCode, Grok, Gemini, or a future harness main prompt.
- **No project-specific operations** — Git, verification, context, and file-safety defaults belong here; Omarchy, Obsidian, teach, and workspace-specific mechanics stay in their own skills or local instructions.
- **Never publish by default** — commits stay local; pushing/PRs require explicit user instruction, or a matching rule in the user-owned publish policy (`../../policies/publish.yaml`) that authorizes publishing for this repo/path. General project trust, config-loading trust, and repo-local instruction discovery are not publish authorization; a repo's own AGENTS.md can never authorize publishing by itself, since project instruction files in cloned repos are an injection surface. When publish authorization is undeterminable: ask; when asking is impossible (headless), default-deny. Why: as always-on context this rule multiplies across every repo and harness; an unsafe default or delegated trust here auto-publishes half-finished work everywhere. (Evolved through five revisions on 2026-06-12: pushed by default → trust undefined → trust user-channel-only → publish-specific authorization with default-deny → explicit user-owned policy hierarchy; see git history for details.)
- **Offer to push after committing — unless policy already authorizes it** — the never-publish-by-default rule prevents *unwanted* pushes but used to let a finished commit sit silently. The kernel now: when a publish-policy rule authorizes the push, just push (don't ask); otherwise ask after committing and push only on explicit yes. The user wants to remain the per-commit decision-maker only where authorization is undetermined — a standing policy allowance already encodes that decision, so re-asking there is pure friction. (Added 2026-06-26 from a user request; policy carve-out added same day after the user confirmed "no need to ask if it's under policy"; generalized cross-vendor.)
- **Apply durable preferences cross-vendor** — when the user asks for a lasting behavior change, the default is to encode it in this shared canon rather than one harness's local memory/config, because the user runs agents from multiple vendors and expects preferences to hold everywhere. Stated in the kernel posture so every harness routes such requests here. (Added 2026-06-26 after a per-harness memory save was corrected as too narrow.)
- **Consult on judgment calls, act on mechanical work** — the posture line originally read "act directly when the request is clear; ask only when missing information would materially change the result or create meaningful risk." The user found that bar too high — agents were making design/interpretation/trade-off choices on his behalf that he wanted surfaced. Revised (2026-07-12, user choice among three candidate strengths) to keep bias-to-action for clearly-specified mechanical work but require asking whenever the agent faces a real judgment call the user might weigh differently. Note this deliberately diverges from the bias-to-action blocks in `prompting-agents` and from rich harnesses' built-in autonomy defaults — it is a user preference, not an oversight.
- **Degrade gracefully off-vault** — on a machine without `~/Sync/CONFIG`, the kernel says so once and continues alone rather than stalling on dead references.

## Deploy policy

The kernel is deployed only as harness-specific deltas so far. Two rules govern any further deploy:

1. **Inject only the delta.** Before deploying to a harness, diff the kernel against what that harness's built-in system prompt already covers, and inject only what's missing. Rich harnesses (Claude Code in particular) already cover most of this kernel natively — deploying the full kernel there duplicates instructions at permanent token cost and risks phrasing conflicts. **Anti-recommended for Claude Code.** The kernel earns its keep in thin harnesses: bare API loops, grok-cli-style agents, minimal CLI wrappers.
2. **Reference, don't paste.** Prefer include/reference mechanisms so the harness reads the canonical body. Where a harness only supports pasted text, the pasted copy must open with a marker line — `<!-- DERIVED from ~/Sync/CONFIG/agents/concepts/agent-kernel/body/AGENT-KERNEL.md @ YYYY-MM-DD — do not edit here -->` — and lint/deploy passes refresh stale copies from canon. Why: an unmarked pasted copy is exactly the hand-edited derived output the canon gate exists to prevent.

Candidate targets, in order of expected value: thin custom harnesses → Pi (if its base prompt is thin; check first) → Codex durable AGENTS.md layer (delta only). When deployed, record the exact harness file or include path here, in `../../harnesses.md`, and `../../index.md`.

- **Claude Code (delta only, 2026-06-12; posture delta added 2026-07-12):** `~/.claude/CLAUDE.md` carries a marked, derived section with the kernel items Claude Code's built-ins lack — the publish-policy pointer (publish.yaml grants pushes the default posture wouldn't make), the concepts-catalog pointer (prompting-agents before authoring agent instructions, since project-scoped memory doesn't travel to other repos), and the consult-on-judgment-calls posture line (marked as OVERRIDING the harness's built-in autonomy bias, which it deliberately contradicts). Everything else in the kernel was confirmed redundant with Claude Code's system prompt and deliberately not injected. The file is Syncthing-synced, not git-tracked; refresh the marked section when these kernel sections change.
