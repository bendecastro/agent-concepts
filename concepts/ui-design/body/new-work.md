# New work: direction before decoration

Frame the subject, audience, task and surface before choosing a style. Write a proportional thesis and token plan before building:

- **Visual thesis:** mood, material and energy.
- **Content plan:** section sequence and each section’s job.
- **Interaction thesis:** meaningful motion ideas suited to the surface.
- **Tokens:** 4–6 named colours, type roles, spacing, surfaces and focus; name a signature element and layout concept.

Critique against the task and references: would another designer arrive at the same place? Revise generic choices and say what changed and why. A signature must serve the subject, not be a novelty pasted onto every screen. Use the project's stack rather than imposing a framework.

Reject unconsidered attractors: cream (~#F4F1EA) + high-contrast serif + terracotta; near-black + acid accent; broadsheet hairlines; purple on white; default font stacks (Inter/Roboto/Arial/system); generic SaaS card grids. These are not forbidden when the subject specifically justifies them; generic “premium” or “craft” is not such a justification. Avoid dark-mode bias and use semantic color roles rather than a preset palette.

## Choose the right surface

- **Landing page:** make the brand and one visual anchor clear in the first screen. Give the hero a focused budget: brand, one headline, supporting line, primary action and dominant image as appropriate. No hero cards or stat/pill soup by default. Full bleed suits some briefs, not all; avoid busy image behind text. Each section explains, proves, deepens or converts rather than repeating itself. Header plus hero should fit the initial viewport at common sizes: subtract fixed header height from a 100svh hero (e.g. `calc(100svh - header-height)`) or overlay it.
- **Product/dashboard:** put working data, filters and actions first. Use utility copy and task-appropriate density, not a marketing hero; use cards when they serve interaction or grouping, not as the default layout. If removing a card’s border, shadow, background and radius does not hurt interaction or understanding, remove the card treatment. Scanning only headings, labels and numbers, can an operator understand the page? Rewrite any sentence that could appear in a homepage hero or ad.
- **Other surfaces:** follow host and task conventions, with no assumption that a marketing composition fits a popup, terminal or native application.

Images should do narrative work; use appropriate real-looking, in-context imagery when the subject calls for it, with readable crops. If generating images, explore options and select deliberately; don't hotlink without permission. Motion should clarify change or establish atmosphere, not satisfy a quota; honor reduced motion. Use concise product language, not design commentary or filler. Limit typefaces and accents when more would dilute hierarchy, but let the brief and existing system decide.

Inspect the render: is the purpose immediately recognizable, the primary action apparent, each section useful, and every decorative device justified? Would hierarchy survive without shadows? Test behavior separately.
