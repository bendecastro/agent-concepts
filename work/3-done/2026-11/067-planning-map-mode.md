# Planning gets a map mode for work too big for one session

Why: `bc-plan-to-pipeline` assumes one grill settles every decision before it drafts a PRD and slices. An effort whose decisions need research, a prototype, a task first, or the owner's later thought has no home between sessions: decisions get made in chat and copied into items by hand (the kernel-in-every-install item), and the swarm review-loop rule's "return to planning" has nowhere to land. Matt Pocock's wayfinder skill (`docs/research/raw/ingested/pocock-wayfinder/`) solves this with a map of decision tickets; most of its other parts already exist here.
Done when: On the pressure-test model, a planning session on a vague idea whose grill leaves a question this session cannot settle writes a map item (not a PRD or build steps), and a small idea with nothing left open still goes straight to PRD and slicing, each 3 of 3 with master failing the map case at least once; the narrowed map workflow is checked by reading and both changed-arm regressions are recorded.

## Requirements

Owner decision (2026-11-28): after two blocking reviews exposed new sequences, the review stop rule sent this back to the owner. The owner narrowed map mode instead of adding special cases for dependency transfer, tracker authority and Slice.

- **When it is a map.** Only a new idea can become a map. After the grill, a question this session cannot settle (research, prototype, a task first, or the owner's "not sure yet") leads to charting; none leads to ordinary planning. For a new idea the owner can override either way; never guess an unsettled answer. An existing item keeps its `Kind:` and uses the absent-owner handling (`Waiting on owner:` if needed) or records `Needs owner:` instead of becoming a map.
- **Where a map lives.** A `Kind: map` work item with a pickup line, or `docs/changes/<slug>/map.md` without a work table. A request to file the map itself in GitHub becomes one idea line in `work/0-ideas.md`, not a map issue or typed child issues.
- **Map sections.** Destination (what reaching the end looks like, one or two lines); Decisions so far (one line per resolved decision pointing to where its detail lives — a decision lives in one place); Not yet specified (in-scope questions not yet sharp enough to be a step; graduate to steps as the frontier advances); Out of scope (ruled beyond the destination; never graduates). Steps are decision steps, each typed grilling, research, prototype or task, using the existing skills (`bc-grilling` + `bc-domain-modeling`, `bc-research`, `bc-prototype`); a step is created only when its question can be stated sharply.
- **Working the map.** Resolve one decision step per session (research can run in parallel), record its answer, graduate newly answerable questions and rule out-of-scope work out. Apply the same recording and graduation to research that returns during charting. Charting ends with its report; mark nothing ready.
- **When the way is clear.** Slice is a fresh `/bc-plan-to-pipeline` run with the map as a settled source. Ordinary dependency, go-ahead and readiness rules apply unchanged to new build items whose `Source:` names the map. Once the artifacts and any required issues exist, tick Slice and put Decisions so far in Outcome; move a map item to done. For a change-folder map, `prd.md` and `tasks.md` are alongside `map.md`, which holds the Outcome.
- **Credit.** [Matt Pocock's wayfinder skill (MIT)](../../docs/research/raw/ingested/pocock-wayfinder/SOURCE.md) is credited in CONCEPT.md.
- **Test.** Preserve the master-vs-changed evidence and rerun one changed-arm map scenario and one settled scenario on Terra low (`openai-codex/gpt-6.1-terra`) via the existing sandbox and RPC driver. Quota exhaustion is PARTIAL; do not substitute.
