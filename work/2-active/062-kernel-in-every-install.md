# Every install method brings the kernel, as the Pi package does

Why: The kernel is a core piece of the bundle, but only Pi users get it by default. Claude Code and Codex users are told to clone the repository and add the kernel plugin from a local path, although the marketplaces they already add from the GitHub tag list `agent-kernel`; `npx skills` users must run `packages/agent-kernel/install.py` from a checkout. `concepts/agent-kernel/CONCEPT.md` also calls the kernel "Anti-recommended for Claude Code" (duplicates built-ins, about 3,000 tokens a session), a claim no test has checked since the kernel gained rules Claude Code lacks.
Done when: The README's Claude Code and Codex boxes install the kernel from the release tag with no checkout (in the default command for Codex, and for Claude Code only if a with/without test on Haiku shows it helps); `npx agent-concepts kernel install <file>` installs the kernel into a named instructions file and each `npx skills` agent box shows its file; the CONCEPT.md Claude Code verdict matches the test.

## Requirements

Owner decisions (2026-11-28, in chat): 1a default in Claude Code and Codex, after a with/without test on Claude Code; 2a an `npx` installer for other agents; 3a plan as a work item. Then 1a test on Claude Code with Haiku; 2a if Haiku shows no gain, Claude Code keeps the kernel optional but installed from the GitHub tag; 3a the user names the instructions file; 4a Codex gets the kernel by default with no behaviour test, once it installs from the tag.

- **Install from the tag.** `claude plugin marketplace add bendecastro/agent-concepts#vX.Y.Z` and `codex plugin marketplace add bendecastro/agent-concepts --ref vX.Y.Z` already register `agent-kernel` (`.claude-plugin/marketplace.json`, `.agents/plugins/marketplace.json`). Prove `claude plugin install agent-kernel@agent-concepts --scope user` and `codex plugin add agent-kernel@agent-concepts` work from a tag-added marketplace, in `scripts/fresh_install_test.py` (no model call), and that the kernel text reaches the session (Claude: SessionStart hook output; Codex: the hook after trust).
- **Codex default.** The Codex box's install command adds the kernel plugin, and says once: trust the SessionStart hook in `/hooks`, or the kernel does not load. Uninstall removes both plugins.
- **Claude Code test.** A with/without pressure run inside Claude Code on Haiku (`claude --model` Haiku), kernel loaded through the plugin vs not, on existing kernel scenarios in `concepts/agent-kernel/tests/` that cover rules Claude Code's own prompt lacks (at least the question-is-not-an-edit, argue-for-the-best-outcome and bare-yes scenarios). Graded from artifacts, per AGENTS.md's Test operation; results file in `concepts/agent-kernel/tests/`. Kernel helps = treatment holds where baseline fails on at least one scenario and regresses on none.
- **Claude Code outcome.** Helps: the default install command adds the kernel plugin; CONCEPT.md drops "Anti-recommended for Claude Code" and cites the results. No gain: the box shows an optional kernel line from the tag (no checkout); CONCEPT.md keeps the verdict and cites the results.
- **`npx` installer.** `package.json` gains a `bin` (for example `agent-concepts`) whose `kernel install <file>` and `kernel remove <file>` run the same marked-block logic as `packages/agent-kernel/install.py`, from the npm package, with no checkout. One implementation, not two copies: either the bin calls `install.py` (needs `python3`; say so) or `install.py` is replaced by the bin and its tests move with it. The packed tarball must contain the kernel bytes it installs. Each `npx skills` agent box names its instructions file (Cursor, Gemini CLI, GitHub Copilot, OpenCode V1; "Any other agent": the file your agent loads).
- **Docs.** README "Optional agent kernel" keeps the two-sentence description and keeps only disable/remove/pin details in its fold; `docs/guides/harnesses.md#standalone-kernel`, `concepts/agent-kernel/CONCEPT.md` (Opt-in packages), CHANGELOG `[Unreleased]` and `index.md` match. `scripts/release_check.py` still passes, and any new tag in the README Install section is the release tag.
