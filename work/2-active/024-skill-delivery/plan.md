# Skill delivery: install these skills outside this repository

Why: people outside this repository cannot install its skills reliably. Skills link into each other's folders, name the owner's private tools, clash with common names, and the only installer assumes a clone and overwrites existing skills.
Done when: a tagged release installs on Linux and macOS through the Claude Code plugin, the Codex plugin, the Pi package and `npx skills`, proven by the fresh-install test in CI; every public skill has a `bc-` name, refers to other skills by name and works without the owner's tools; the README documents each method; requirements in [requirements.md](requirements.md).
Stage: next
Blocked by: nothing
Kind: feature
Source: bc-plan-to-pipeline
Planned: bc-plan-to-pipeline 2026-11-25
Ready for agent: yes

## Steps

- [ ] Public skill list: a script (or lint mode) generates the list of public skills and the skills each needs, from `concepts/relationships.json` `loads` edges and the `deployed:` status; kernels are excluded. Lint fails when a body names another public skill that is not on its needed list. Stories 4, 5. Done when the generated list is committed, lint has 0 ERROR, and a test shows the new check failing on a body that names an unlisted skill. Out of scope: renaming, rewriting links, packaging.
- [ ] Name references: replace every relative link from one concept's `body/` into another concept's folder with a reference by skill name (and section where useful); replace each link to the kernel's storage-safety section with a short self-contained rule in that skill; update `concepts/relationships.json` and regenerate the relationship views. Lint gains a check rejecting cross-concept body links. Blocked by: Public skill list. Story 5. Done when `rg '\.\./\.\./[a-z-]+/body' concepts/*/body` finds nothing, the new lint check fails on a reintroduced link, and lint has 0 ERROR. Out of scope: renaming skills; changing what a skill teaches.
- [ ] Generic wording for owner tools: in `agent-kernel`, `bc-init-agent`, `bc-pipeline-to-done`, `bc-wiki-maintain`, `bc-work-sync` and `tdd`, describe each step that names an owner tool (`bc-ask`, `bc-pytest`, `bc-offload`, `bc-storage-health`, `publish-check`, `$AGENT_CONCEPTS`) generically, keeping the private-overlay line; list in the step notes which tool names the owner's overlays must now carry. Discipline concepts whose rules change re-run their pressure tests. Story 7. Done when `rg 'bc-(ask|pytest|offload|storage-health)|publish-check' concepts/*/body` finds nothing outside overlay lines, lint (including personal terms) has 0 ERROR, and the gate is green. Out of scope: writing the owner's private overlays (the integrating session does that on the owner's machines).
- [ ] `bc-` rename: rename every public skill without the prefix (`git mv`, frontmatter `name:`, relationships, index, README, guides, tests, other bodies' name references); add each old name to the deploy-alias list in `scripts/deploy-local-skills.py`; lint gains a check that every public skill name starts with `bc-`. Historical records keep old names. Blocked by: Name references; Generic wording for owner tools. Stories 6, 11. Decision 0001. Done when the prefix check passes, every old name resolves through an alias after `deploy-local-skills.py` runs in a scratch HOME, lint has 0 ERROR and the gate is green. Out of scope: renaming mentions in the owner's other projects.
- [ ] Contributor installer: `deploy-local-skills.py` skips (and reports) an existing skill it did not create instead of replacing it, and gains an uninstall that removes only links it created. Story 12. Done when tests (scratch HOME via the test runner's temp folder) show a foreign skill kept, own links replaced, and uninstall leaving foreign skills intact, each failing before the change. Out of scope: plugin and package formats.
- [ ] Pi package: package description so `pi install git:github.com/bendecastro/agent-concepts@<tag>` installs every public skill; Pi-only skills say so in their description. Blocked by: `bc-` rename. Story 3. Done when `pi install` from a local path into a scratch HOME lists every public skill and `pi remove` removes them. Out of scope: CI wiring (fresh-install test step).
- [ ] Claude Code plugin: one plugin with every public skill plus a marketplace file in this repository, version matching the release. Blocked by: `bc-` rename. Story 1. Done when Claude Code in a scratch HOME adds the local marketplace, installs the plugin and lists the skills (or, if listing needs login, the installed files match the public skill list). Out of scope: other marketplaces.
- [ ] Codex plugin: same as the Claude plugin, in Codex's plugin format. Blocked by: `bc-` rename. Story 2. Done when Codex in a scratch HOME installs the plugin and its skills are present per the public skill list. Out of scope: other marketplaces.
- [ ] `npx skills` packs: generate the documented commands (all skills; each ready-made pack with its needed skills) from the public skill list. Blocked by: `bc-` rename. Stories 4, 5. Done when each generated command run against a local checkout in a scratch HOME installs exactly the listed skills. Out of scope: changes to the `skills` tool.
- [ ] Fresh-install test in CI: first record whether each agent can list skills without login; then a CI job on Ubuntu and macOS that, per method, installs into `HOME=$(mktemp -d)`, checks the skills are listed (or present), needed skills are present and one bundled helper runs, updates and uninstalls. Blocked by: Releases. Stories 1–4, 8, 9. Done when lint has 0 ERROR (links resolve) and every command in the section is one the fresh-install test runs. Out of scope: a website.
